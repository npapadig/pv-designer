# Μπαταρίες (αποθήκευση ενέργειας) — σχεδιασμός και κομμάτια

Ζήτηση Νίκου (2026-11-02): «να προσθέσουμε επιλογή για μπαταρίες, για όλα τα έργα. Ο χρήστης να λέει για πόσες
μέρες να κρατήσει εφεδρεία αν πέσει το δίκτυο, ή να επιλέγει ισχύ και όσα χαρακτηριστικά χρειάζεται, ή να
υπάρχουν αυτόματα (ανάλογα με το μέγεθος των πάνελ), ή προτάσεις όπως στην τοποθέτηση των πάνελ».
Ο Νίκος έβαλε τον συντονιστή σε max effort για τον σχεδιασμό. Κανόνας του Νίκου (2026-11-02, από την τοποθέτηση
πάνελ): οι ρυθμίσεις που δίνει ο χρήστης ΠΑΝΩ ισχύουν σε ΟΛΕΣ τις κάρτες προτάσεων· καμία κρυφή προεπιλογή.
Μια πρόταση αλλάζει μόνο ό,τι ορίζει η ίδια (εδώ: τη χωρητικότητα).

## 1. Τι είναι (απλά)
- Η μπαταρία αποθηκεύει ρεύμα (kWh = η «δεξαμενή») και το δίνει όταν χρειάζεται (kW = πόσο γρήγορα βγαίνει).
- Δύο λόγοι να υπάρχει: (α) **εξοικονόμηση**: αποθηκεύει την περίσσεια του ήλιου της ημέρας και την ξοδεύεις το
  βράδυ αντί να τη χαρίζεις/πουλάς φθηνά και να αγοράζεις ακριβά· (β) **εφεδρεία**: αν πέσει το δίκτυο, κρατά
  ό,τι διάλεξες (ψυγείο, φώτα, router…) για Χ ημέρες.
- **Αυτονομία (ημέρες)** = χρήσιμη ενέργεια της μπαταρίας ÷ ημερήσια ενέργεια των φορτίων που θες να κρατήσεις.
- Οι δύο λόγοι μαλώνουν λίγο: αν η μπαταρία αδειάζει κάθε βράδυ για εξοικονόμηση, όταν πέσει το δίκτυο μπορεί
  να είναι μισοάδεια. Γι' αυτό υπάρχει η **εφεδρεία που κρατιέται πάντα (%)**: 0 % = μόνο εξοικονόμηση,
  100 % = μόνο εφεδρεία, ενδιάμεσα = και τα δύο.

## 2. Πού μπαίνει στην εφαρμογή
Νέο βήμα **«Μπαταρία»** μετά την «Παραγωγή» και πριν τα «Οικονομικά» (θέλει την ωριαία παραγωγή και τροφοδοτεί
τα οικονομικά). Βήματα πλέον 8. Διακόπτης «Θέλω μπαταρία» (προεπιλογή ΚΛΕΙΣΤΟ): με κλειστό, όλα τα νούμερα της
εφαρμογής μένουν ΑΚΡΙΒΩΣ όπως πριν (baseline). Ισχύει σε όλους τους τύπους έργου (ταράτσα, κεκλιμένη, πάρκο).

## 3. Δεδομένα (μοντέλο)
Αποθηκεύονται στο έργο ως `battery: {enabled, inputs, result}` (όπως το `electrical`).

**Φορτία (κατανάλωση)**
- `annual_kwh` ετήσια κατανάλωση (από λογαριασμό). Κοινό πεδίο με το `finConsumption` των οικονομικών (συγχρονίζονται).
  Αν είναι κενό → ΕΚΤΙΜΗΣΗ: κατανάλωση = ετήσια παραγωγή (σύστημα μεγέθους όσο η κατανάλωση, η συνηθισμένη πρακτική στον
  συμψηφισμό)· η εφαρμογή το γράφει καθαρά ως υπόθεση.
- `profile` τύπος καταναλωτή (ωριαίο σχήμα 24 ωρών): σπίτι (πρωί+βράδυ), σπίτι με κλιματιστικά ημέρας, γραφείο/επαγγελματικό
  ημέρας, 24ωρη επιχείρηση (ψυγεία), αγρόκτημα/άντληση ημέρας, σταθερό. `season` εποχικότητα: καλοκαίρι-κορυφή
  (κλιματισμός), χειμώνας-κορυφή (θέρμανση), σταθερή. Όλα εκτιμήσεις, ορατά και αλλάξιμα.
- **Εφεδρικά φορτία**: πίνακας συσκευών (όνομα, kWh/ημέρα, W κορυφής, τικ) με έτοιμα σύνολα «Βασικά» (ψυγείο,
  καταψύκτης, φωτισμός, router, TV, φορτιστές ≈ 3-4 kWh/ημέρα), «Άνετη» (+πλυντήριο, μικροκύματα, ένα κλιματιστικό,
  αντλία ≈ 9 kWh/ημέρα) και «Όλο το σπίτι» (= μέση ημερήσια κατανάλωση, κορυφή από το κεντρικό διακόπτη).
  Κορυφή ισχύος = Σ W × συντελεστής ταυτοχρονισμού (70 %). Δεν μοντελοποιείται ρεύμα εκκίνησης (surge) συσκευών.
- `target_days` στόχος ημερών αυτονομίας (προεπιλογή 1).

**Μπαταρία**
- `capacity_kwh` ονομαστική, `usable_pct` (βάθος εκφόρτισης DoD, προεπιλογή 90 %), `power_kw` μέγιστη ισχύς
  φόρτισης/εκφόρτισης (προεπιλογή = C/2: 0,5 kW ανά kWh, ανάλογα το μοντέλο), `roundtrip_pct` απόδοση φόρτισης-εκφόρτισης
  (προεπιλογή 90 % από AC σε AC), `reserve_pct` (βλ. §1), `coupling` ac/dc (v1: ίδια απόδοση, μόνο ένδειξη),
  `cost_per_kwh` και `cost_fixed` (€, με ΦΠΑ), `subsidy_eur`, `life_years`/`cycles` και `fade_pct_per_year` (απώλεια
  χωρητικότητας), `replacement_year`. Προεπιλογές ΕΝΔΕΙΚΤΙΚΕΣ (δεν είναι επαληθευμένες τιμές αγοράς) και σημειωμένες ως τέτοιες.
- Έτοιμα γενικά μεγέθη (5, 10, 15, 20 kWh) στην αρχή· αργότερα κατάλογος πραγματικών μοντέλων (§8).

## 4. Υπολογισμοί (το μαθηματικό μοντέλο)
Όλα σε ωριαίο βήμα (8760 τιμές) όταν χρειάζεται παραγωγή. Η παραγωγή PV είναι η ωριαία AC της αναλυτικής
προσομοίωσης (`simulation.simulate`, καιρός PVGIS TMY από cache). Η κατανάλωση = ετήσια × εποχικότητα × ωριαίο σχήμα.

**Α. Αυτονομία χωρίς ήλιο (κλειστός τύπος, v0.30)**
- `E_day` = ημερήσια ενέργεια εφεδρικών φορτίων (kWh/ημέρα), `P_peak` = κορυφή (kW).
- `η_dis = √(roundtrip)` (η απώλεια εκφόρτισης· η απώλεια φόρτισης έχει ήδη «πληρωθεί»).
- Χρήσιμη ενέργεια `C_u = capacity × usable%`. Εγγυημένη (εφεδρεία) `C_g = C_u × reserve%` (με reserve 0 % δεν
  εγγυάται τίποτα, γι' αυτό η ένδειξη «αν είναι γεμάτη»).
- Ημέρες αυτονομίας: `C_u × η_dis / E_day` (γεμάτη) και `C_g × η_dis / E_day` (εγγυημένη).
- Χωρητικότητα που χρειάζεται για N ημέρες: `capacity = E_day × N / (η_dis × usable% × reserve%)`
  (με reserve% < 100 η εγγυημένη ενέργεια ζυγίζεται μόνο στο μέρος της εφεδρείας).
- Έλεγχος ισχύος: `power_kw ≥ P_peak` αλλιώς «η μπαταρία δεν αντέχει τα φορτία ταυτόχρονα».

**Β. Ωριαία λειτουργία (dispatch, v0.31)**
Κάθε ώρα h: `direct = min(pv, load)`, `surplus = pv − direct`, `deficit = load − direct`.
Φόρτιση `ch = min(surplus, power, (soc_max − soc)/η_ch)`, `soc += ch × η_ch`, `export = surplus − ch`.
Εκφόρτιση `dis = min(deficit, power, (soc − soc_floor) × η_dis)`, `soc −= dis/η_dis`, `import = deficit − dis`.
`soc_floor = soc_min + reserve% × C_u`. `η_ch = η_dis = √roundtrip`. Δεν φορτίζει και εκφορτίζει την ίδια ώρα.
Αποτελέσματα: ιδιοκατανάλωση % = (PV − export)/PV, αυτάρκεια % = 1 − import/load, ισοδύναμοι κύκλοι/έτος,
ενέργεια ανά ώρα για γράφημα τυπικής ημέρας (καλοκαίρι/χειμώνας). Χωρίς μπαταρία = ίδιος υπολογισμός με 0 kWh.
Ταυτόχρονος υπολογισμός πολλών χωρητικοτήτων με numpy (διάνυσμα ανά ώρα) για τις προτάσεις.

**Γ. Διακοπή δικτύου με ήλιο (v0.31/0.32)**
Για κάθε μέρα του έτους ως αρχή της διακοπής (μπαταρία στο επίπεδο που εγγυάται η εφεδρεία) και μέχρι 30 ημέρες:
μόνο εφεδρικά φορτία, παραγωγή PV διαθέσιμη (χωρίς εξαγωγή), μέχρι να αδειάσει η μπαταρία. Αναφέρεται ανά μήνα
(ελάχιστο / μέσο) ώστε να φαίνεται η διαφορά Δεκέμβρη–Ιουλίου. «>30» = ουσιαστικά αόριστα.

**Δ. Οικονομικά (v0.31)**
`finance.py` παίρνει προαιρετικά `battery`: επιπλέον κόστος (`cost_per_kwh × kWh + cost_fixed − subsidy`), αντικατάσταση
στο έτος `replacement_year` (κόστος × (1 − πτώση τιμών %/έτος)), και ανά έτος `self_kwh`/`export_kwh` από το
dispatch με υποβάθμιση PV και απώλεια χωρητικότητας (προσομοίωση ανά έτος ή σε κόμβους + παρεμβολή). Οι υπάρχοντες
τύποι σύνδεσης (self/net_billing/net_metering) μένουν· αλλάζει μόνο ο διαχωρισμός ιδιοκατανάλωση/εξαγωγή.
Με net metering η μπαταρία αξίζει συχνά λιγότερο (το δίκτυο λειτουργεί ήδη σαν «μπαταρία»): η εφαρμογή το λέει ειλικρινά.
ΑΡΧΗ: «τα νούμερα είναι ιερά» — αν δεν συμφέρει, το αποτέλεσμα λέει «δεν αποσβένεται» και όχι ωραίους αριθμούς.

**Ε. Προτάσεις (κάρτες, όπως στα πάνελ)**
Κάθε κάρτα = μια χωρητικότητα (και ισχύς), με kWh, kW, κόστος, ιδιοκατανάλωση %, αυτάρκεια %, ημέρες αυτονομίας, απόσβεση.
1. **Βασική εφεδρεία** — ημέρες στόχου με τα «Βασικά» φορτία (κλειστός τύπος).
2. **Άνετη εφεδρεία** — ημέρες στόχου με τα «Άνετη» φορτία.
3. **Οικονομική** — χωρητικότητα με το καλύτερο NPV (v0.31/0.32, από sweep· αν καμία δεν συμφέρει, το λέει).
4. **Για το βράδυ** — μέγεθος ≈ τη νυχτερινή κατανάλωση (v0.30 κανόνας: ~1 kWh ανά kWp για καθημερινή χρήση).
5. **Χειροκίνητα** — οι ρυθμίσεις όπως είναι.
Οι κάρτες 1,2,4 αρχικά με κανόνες (χωρίς ωριαίο υπολογισμό)· από v0.32 υπολογίζονται με sweep.

## 5. Τι αφορά ΔΕΝ μοντελοποιείται (εκ προθέσεως, να λέγεται)
Ρεύμα εκκίνησης συσκευών, φάσεις (τριφασικός inverter ανά φάση), θερμοκρασιακή υποβάθμιση, χρονοδιάγραμμα
τιμολογίου (νύχτα/δυναμικό) και φόρτιση από το δίκτυο (μελλοντικό κομμάτι)· επίσης ρυθμιστικό πλαίσιο/άδειες και
προγράμματα επιδότησης (οι αναζητήσεις 2026-11-02 έδειξαν προγράμματα κυρίως για επιχειρήσεις/ΟΤΑ και μόνο
πίσω από τον μετρητή με φόρτιση από το ίδιο το ΦΒ· ΜΗ επαληθευμένο για νοικοκυριά — ο Νίκος να ελέγξει).

## 6. Κομμάτια (μικρές εκδόσεις)
- **v0.30.0** Βήμα «Μπαταρία» με εφεδρεία: φορτία, ημέρες, χωρητικότητα, ισχύς, αυτονομία (κλειστός τύπος), προτάσεις με κανόνες, αποθήκευση στο έργο, αγγλικά, βοήθεια. `backend/battery.py`, `frontend/battery.js`.
- **v0.31.0** Ωριαίος υπολογισμός (ιδιοκατανάλωση/αυτάρκεια/γράφημα ημέρας), προφίλ κατανάλωσης, ενσωμάτωση στα οικονομικά.
- **v0.32.0** Προτάσεις με sweep (οικονομική κ.λπ.), διακοπή με ήλιο ανά μήνα.
- **v0.33.0** Κατάλογος πραγματικών μπαταριών (ροή «batteries-catalog», Sonnet, με πηγές όπως στους inverters) + PDF αναφοράς, μονογραμμικό, τεχνική περιγραφή, κινητό.
- Αργότερα (ρώτα Νίκο): νυχτερινό/δυναμικό τιμολόγιο και φόρτιση από δίκτυο, υβριδικοί inverters στον κατάλογο.

## 9. Σχήμα δεδομένων στο έργο (σύμβαση για τα έγγραφα: PDF, μονογραμμικό, κινητό)
Το `project.battery` (αποθηκεύεται από το `frontend/battery.js`, `collect()`):
```
battery: {
  enabled: true,                       // αν είναι false/λείπει: καμία αλλαγή στα έγγραφα
  set: "basic|comfort|house|custom",   // σύνολο φορτίων εφεδρείας
  rows: [{key, name, kwh_day, peak_w, on, custom?}],   // φορτία (on = μετράει)
  inputs: {batDays, batCap, batPower, batUsable, batRound, batReserve, batSimul, batCost, batFixed, batSubsidy,
           batFade, batReplYear, batReplPct, batProfile, batSeason},   // ΟΛΑ ως ΚΕΙΜΕΝΟ· κενό = αυτόματο/προεπιλογή
  result: {                            // απάντηση του POST /api/battery/autonomy (v0.30)
    daily_kwh, peak_kw, target_days, needed_capacity_kwh, needed_power_kw,
    battery: {capacity_kwh, power_kw, power_auto, usable_kwh, guaranteed_kwh, days_full, days_guaranteed,
              capacity_ok, power_ok, capex, investment},
    cards: [...]
  },
  dispatch: {                          // v0.31, ΜΟΝΟ αν ο χρήστης έτρεξε «Υπολογισμός εξοικονόμησης»· αλλιώς λείπει/null
    production_kwh, load_kwh, assumed_consumption,      // ετήσια παραγωγή PV (ωριαία προσομοίωση), κατανάλωση, αν η κατανάλωση ΥΠΟΤΕΘΗΚΕ
    capacity_kwh, power_kw, usable_kwh, reserve_pct,
    without: {self_kwh, export_kwh, import_kwh, self_consumption_pct, autarky_pct},
    with:    {self_kwh, export_kwh, import_kwh, self_consumption_pct, autarky_pct, charged_kwh, discharged_kwh, cycles},
    monthly: [{month, production_kwh, load_kwh, import_without_kwh, import_with_kwh, export_without_kwh, export_with_kwh}],
    source, warning
  }
}
```
και το `project.finance.battery` (v0.31, μόνο όταν τα οικονομικά υπολογίστηκαν με μπαταρία):
`{capex, investment, replacement_year, replacement_cost, extra_investment, first_year_gain, payback_years, npv_gain, irr_pct,
  self_consumption_without_pct, self_consumption_with_pct, autarky_without_pct, autarky_with_pct}`.
Όλα τα πεδία εκτός των `enabled/inputs/result` μπορεί να λείπουν· τα έγγραφα πρέπει να αντέχουν στην απουσία τους.
